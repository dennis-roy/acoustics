### Generate offline fixtures

Run `python3 bench/simulate.py tone tone.acou` from the repository root. The script uses the standard library, checks the golden frame, and creates a new output file. Other cases are `silence`, `clipping`, `gap`, `corruption`, and `restart`. At the default rate, complete runs contain 25,600 synthetic samples. Silence and clipping are structurally complete but should exercise measurement-quality checks. Gap and corruption must invalidate the run. Restart must invalidate the incomplete first run and allow the second run to complete.

### Firmware and evaluator handoff

Build the capture library on the CM5 with `PICO_SDK_PATH` set to the existing SDK checkout. Run `cmake -S firmware -B build/pico -DPICO_BOARD=pico2_w` and `cmake --build build/pico --target acoustic_capture`. Task 7 adds the USB executable and UF2. The Acoustic core workflow also builds the library for Pico 2 W and runs the native filter and Python evaluator checks. Inspect the run for the commit being used.

The capture API accepts the verified clock GPIO, data GPIO and sampling half-cycle at runtime. Board pin mapping and electrical levels still require the actual KAS-700-0164 assembly documentation. Treat the 3.2 MHz PDM clock as a prototype candidate until the fitted microphone's operating mode is confirmed. The four-cycle PIO loop samples halfway through the selected clock level. The 16.8 divider must represent the requested average clock exactly. Check real duty cycle, edge setup/hold, frequency and settling with an oscilloscope. [Pico SDK PIO](https://github.com/raspberrypi/pico-sdk/tree/2.2.0/src/rp2_common/hardware_pio) · [Pico SDK DMA](https://github.com/raspberrypi/pico-sdk/tree/2.2.0/src/rp2_common/hardware_dma)

One 32-bit DMA word holds 32 chronological PDM samples and yields one 100 kHz PCM sample. One core owns capture and passes a private word array to `pdm_capture_read`. Drain frequently. The 8192-word ring holds 81.92 ms at the design rate. A stalled FIFO or full ring latches an integrity fault. Propagate flags to stream v1, invalidate that run and start a fresh session after recovery. Enforce a run timeout below the DMA transfer limit of roughly 44 minutes. Check status after the last read and before closing. Benchmark concurrent USB, DSP and capture, including an intentional consumer stall longer than the ring duration.

Zero-initialize the decimator for each new capture. Task 7 must clock the microphone through its verified settling interval, then feed at least 40 PCM words through the filter before retaining samples. Start transmitted sample indices at zero after warm-up. CIC3 reduces the bit rate by eight with unsigned modular arithmetic. The 129-tap FIR runs at 400 kHz and emits every fourth input. Its coefficients window an inverse-CIC passband response up to the 50 kHz design cutoff. Keep 0–40 kHz as the candidate analysis band. Independent numerical replay of the deterministic 0.30 FS reference yielded RMS-derived amplitudes of 0.3000, 0.2977, 0.2900, 0.0040, 0.0020 FS at 1, 30, 40, 65 and 360 kHz respectively. These calculations include modulation noise. Physical response, alias rejection across the band, sustained real-time throughput, and repeatability require bench measurements.

Task 8 calls `bench.evaluate.evaluate` with a signed 16-bit NumPy array, validated completion state, latched status, stream source, rate, model and recipe. Results retain measured values, limits and recipe revision. Declare a transport fault even if recovered samples look plausible. The example recipe exercises synthetic limits. Valid microphone runs remain HOLD until independently validated limits exist. Suspected component is unknown pending labelled fault evidence.
